# Deploying the backend (Render + Neon)

Nothing here has been run for you. The API runs as **one** Render web service built from `backend/Dockerfile`, and stores data in a Neon Postgres database. The blueprint is `render.yaml` at the repo root.

> **Single instance only.** Rate limits live in the app's memory. A second instance would double the limits and split their counters. Do not scale out without first moving the limiter to a shared store.

> **Free plan sleeps.** Render's free web services spin down after a period with no traffic (about 15 minutes at the time of writing; check Render's current terms) and take a while to wake on the next request. The game copes: sync retries with backoff and the leaderboard shows a Retry button, so a cold start is a delay, not a failure. Before the Play Store release, move the service to a paid instance so it stays awake. Use Neon for the database either way; Render's own free Postgres expires.

## 1. Create the database (Neon)

1. Sign up at neon.tech and create a project. Pick a region near the Render region you will use (`render.yaml` says `frankfurt`; change both together).
2. On the project dashboard, copy the **connection string** (it starts with `postgresql://` and ends with `?sslmode=require`). Paste it as-is later; the backend converts it for its async driver.

## 2. Create the service (Render)

1. Push this repo to GitHub (it is already there) and sign up at render.com with GitHub.
2. Dashboard > **New** > **Blueprint**, pick the repo. Render reads `render.yaml`.
3. It asks for the two values the file does not store:
   - `DATABASE_URL`: the Neon connection string from step 1.
   - `CONTACT_EMAIL`: shown on the privacy page (`/privacy`). Leave it empty to show no contact line.
4. `JWT_SECRET` is generated by Render. In production (`ENVIRONMENT=production`) the app refuses to start with the default or a short secret.
5. Apply. Render builds the image and starts it. The start command runs `alembic upgrade head` first, then the server. Watch the **Logs** tab until you see the server listening, and check that `/health` is green.

The service URL looks like `https://dropgrid-api.onrender.com` (Render adds a suffix if the name is taken; use the URL it shows).

## 3. Smoke test

```sh
BASE=https://dropgrid-api.onrender.com
curl $BASE/health            # the first call after a sleep can take a while

# register (note the access_token in the response)
curl -s -X POST $BASE/v1/auth/register -H 'content-type: application/json' \
  -d '{"email":"smoke@example.com","password":"smoke-test-pw","username":"smoke_test"}'
TOKEN=<paste access_token>

# sync (200 = ok; best_score must be plausible for total_lines)
curl -s -X POST $BASE/v1/sync -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"best_score":1200,"total_lines":10,"games_played":1}'

curl -s $BASE/v1/leaderboard          # smoke_test should be listed

curl -i -X DELETE $BASE/v1/players/me -H "authorization: Bearer $TOKEN"   # 204
curl -s $BASE/v1/leaderboard          # gone again
```

Also open [$BASE/privacy](https://playdropgrid.vercel.app/privacy) (the site hosts the
privacy policy) and `$BASE/account/delete` (the API hosts account deletion) in a
browser. These two URLs are the ones to enter in the Google Play Console — privacy
policy and account deletion links.

## 4. Point the game at it

In `game/project.godot`, set the release URL. It **must end in `/v1`** (the game appends paths like `/auth/register`) and must be HTTPS, with no trailing slash:

```ini
dropgrid/network/api_base_url.release="https://dropgrid-api.onrender.com/v1"
```

Debug builds keep using the LAN or emulator URL. An empty release URL turns every online feature off, so a release build without this line is a clean offline game.

## Later

- **New migration:** commit and push. Render redeploys when files under `backend/` change, and the start command applies the migration before the server starts.
- **Rotate the JWT secret:** Dashboard > Environment > edit `JWT_SECRET`. This signs everyone out.
- **Logs and rollback:** the service's Logs and Events tabs. Rollback by redeploying an earlier deploy from Events.
- **Blueprint changes:** if you edit `render.yaml`, Render asks you to sync the blueprint. If it rejects a key, check the current Blueprint spec at render.com/docs/blueprint-spec; the file was written from memory of that spec and has not been run.
